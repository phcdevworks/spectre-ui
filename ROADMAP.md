# Spectre UI Roadmap

`@phcdevworks/spectre-ui` is the Layer 2 styling contract in the Spectre system.
It consumes the published `@phcdevworks/spectre-tokens` package and turns those
token contracts into reusable CSS entry points and framework-agnostic recipe
APIs.

This document tracks what's next. For what already shipped and why, see
[CHANGELOG.md](CHANGELOG.md) (release-by-release detail) and git history — this
file does not restate delivered work.

## What's Next

Phase 26 catches up with `spectre-tokens` 4.15.0: the `action` colour role
has its button variant, stat unit tone, and quote rail tone, and the
heading and display presets shrink below 768px with the roles. It also closes
the `spectre-base` requests of 2026-10-23 for the text-size floor, prose size,
icon-box glyph size, and the nav/footer container seam. It shipped in 5.8.0
(2026-10-23); downstream repos can update to `^5.8.0`. Future
token releases are caught by `tests/token-parity.test.ts`, which fails until
every newly published variable has a consumer here.

A cross-repo item remains:

- **A downstream documentation consumer's stale Tailwind documentation** — its
  published docs still describe the Tailwind preset/theme export `spectre-ui`
  removed in `3.0.0`. Tracking the fix belongs in that repo's own `TODO.md`, not
  here.

Icon/AspectRatio recipe wrappers (formerly a watched candidate here) were
dropped 2026-08-18 after two evidence checks found no downstream use case. Both
underlying token groups are covered without a recipe: aspect ratios by the
`.sp-aspect-*` utilities (Phase 12) and icon sizes by the `.sp-icon-*` utilities
(Phase 20). Git history for that decision has the full rationale. A recipe
wrapper can still be added proactively if a consumer needs variant logic that a
single utility class cannot express.

Periodic downstream drift audits (grepping `spectre-components`,
`spectre-ui-astro`, and the `project-web` sites for hand-rolled CSS duplicating
a published `spectre-tokens` group with no `spectre-ui` backing) are ongoing
practice, triggered by each new upstream token publish or at minimum once per
minor release — not a tracked backlog item.

New namespace, recipe-family, or contract work beyond the above is planned
proactively, ahead of downstream requests, per the companywide "Proactive
Innovation" rule. Every newly published `spectre-tokens` family is backlog here
as soon as it ships.

## Explicitly Out of Scope

- Do not author tokens or semantic visual meaning here.
- Do not use GitHub-only token changes as synchronization authority.
- Do not invent local visual fallback values (link, divider, nav, modal,
  toast, tooltip, dropdown, or any other) while waiting for token support.
- Do not add framework components, templates, hooks, slots, or runtime behavior.
  This includes icons: the `./icons` subpaths ship SVG data only (an explicit
  scope addition, decided 2026-10-23). Rendering helpers (DOM, SVG strings,
  or components) belong in the adapters. Icons do not belong in
  `spectre-tokens`.
- Do not move adapter-package delivery concerns into this package.
- Do not combine token synchronization, new recipe expansion, and unrelated
  documentation cleanup in one change.
- Do not hand-edit `dist/`, generated snapshots, or other generated files
  such as `src/styles/utilities.generated.css` and
  `src/icons/*.generated.ts`.
